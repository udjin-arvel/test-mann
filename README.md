# Sqoch — тестовое задание 01 (оформление билетов)

Полноценный сценарий покупки билетов на мероприятие «Космос рядом»: выбор сеанса, 1–4 участника с именем и возрастом, один email на заказ, проверка состава и цены, успешное оформление или ситуация «места закончились». Интерфейс адаптирован под десктоп и телефон (от 360 px).

**Стек:** React (TanStack Start/Router) + FastAPI + SQLite.

## Быстрый старт (Docker)

```bash
docker compose up --build
```

- Интерфейс: http://localhost:8080  
- API и OpenAPI: http://localhost:8000/docs

Данные SQLite хранятся в volume `backend-data`.

## Локальный запуск без Docker

### Backend

```bash
cd backend
py -3 -m venv .venv # или просто python -m venv .venv
.venv\Scripts\activate          # Windows
# source .venv/bin/activate   # Linux/macOS
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000
```

База по умолчанию: `backend/data/app.db` (создаётся при первом запросе, сид с четырьмя сеансами).

### Frontend

В отдельном терминале:

```bash
cd client
npm install
npm run dev
```

Откройте http://localhost:8080. Запросы к `/api/*` проксируются на `http://127.0.0.1:8000` (переопределение: `API_PROXY_TARGET`).

### Тесты

```bash
cd backend && .venv\Scripts\python -m pytest
cd client && npm test
```

## Структура репозитория

| Путь | Назначение |
|------|------------|
| [client/src/lib/tickets.ts](client/src/lib/tickets.ts) | Бизнес-правила на клиенте (тесты) |
| [client/src/lib/api.ts](client/src/lib/api.ts) | HTTP-клиент к API |
| [backend/app/tickets.py](backend/app/tickets.py) | Те же правила на сервере |
| [backend/app/orders.py](backend/app/orders.py) | Атомарное бронирование (`BEGIN IMMEDIATE`) |

**Правила заказа:** полный билет 2 000 ₽ (от 14 лет), детский 1 000 ₽ (младше 14). Ребёнок младше 14 может пройти только вместе с участником от 18 лет в том же заказе. Сумма и остаток мест считаются на сервере; клиент не доверяется полю `total` при отправке.

**Демо-режим** на шаге «Проверка» переключает ответ API: успех или имитация гонки за места (`scenario: sold_out`).

Оплата не подключена — после подтверждения показывается экран успеха.

## API (кратко)

- `GET /api/health`
- `GET /api/catalog` — мероприятие, сеансы, правила
- `POST /api/orders` — создание заказа
- `GET /api/orders/{orderId}` — детали заказа

## Как здесь применить LLM, tool calling и RAG?

Ниже — проектирование под AI SaaS-платформу (коммуникации с клиентами, CRM, мессенджеры), без подключения реальной модели в этом репозитории.

### Tool calling (агент с инструментами)

Тот же FastAPI можно обернуть инструментами для LLM:

| Инструмент | Действие |
|------------|----------|
| `list_sessions` | `GET /api/catalog` → сеансы и остатки |
| `quote_order` | валидация состава и расчёт суммы на сервере |
| `create_order` | `POST /api/orders` |
| `get_order` | `GET /api/orders/{id}` |

Модель ведёт диалог («на какой день?», «сколько взрослых и детей?»), собирает слоты и вызывает инструменты. **Цены, правила сопровождения и списание мест** всегда из API, не из «памяти» модели. Контекст диалога — черновик заказа между репликами (session id, участники, email).

Такой агент ложится на сценарий вакансии: один backend, каналы — сайт, чат поддержки, Telegram/WhatsApp через те же tools.

### RAG (база знаний)

В векторный индекс — статичные материалы: описание шоу, адрес и как добраться, возрастные рекомендации, правила сопровождения детей, что взять с собой, политика возврата и тп. На вопрос «можно ли ребёнку 10 лет без взрослого?» модель отвечает с опорой на фрагменты политики.

**PS:** Для «сколько стоит и есть ли места на субботу?» агент вызывает `list_sessions` / `quote_order`.

### Граница ответственности

Бронирование остаётся транзакцией в SQLite (или в production — в PostgreSQL с блокировками). LLM — слой понимания намерения и сбора данных; решение «продать или отказать» принимает только backend. Это снижает риск галлюцинаций с ценами и двойной продажи мест.

### Память диалога

Краткая память: текущий черновик заказа в сессии чата. Долгая: история заказов клиента по email/CRM после `create_order` — для «повторите прошлый заказ» без повторного обхода всех полей.
